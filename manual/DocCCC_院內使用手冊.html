院內使用手冊

本機操作 HTML、FTP 共用單一 JSON 的新手流程。照著紅框編號操作即可；日常使用不需要自行匯入或匯出備份。

圖片資料皆為示範假資料。姓名、日期與評分僅供說明，不是院內真實紀錄。

適用檔案：index.html、milestones.html、FTP 上的 DocCCC-data.json
手冊版本：2026-08-21

先看這一頁

每天的標準流程只有四步

1從每台電腦的本機硬碟開啟 index.html。
2按「開啟 FTP 共用檔案」，選取固定的 DocCCC-data.json；瀏覽器詢問時允許變更。
3看到右上角「FTP JSON 已連結」後，照各頁面的暫存／提交按鈕操作。
4關閉前確認右上角顯示「已同步」；若不確定，按一次「儲存 JSON」。
每台電腦的本機資料夾
  • index.html（評分系統）
  • milestones.html（獨立參考頁）
⇄
FTP 共用資料夾
  • DocCCC-data.json（所有人共用的正式資料）
  • HTML 可備份在這裡，但執行前要複製到本機
不要直接從 FTP／網路位置執行 HTML。目前可靠的院內用法是「本機 HTML ＋ FTP JSON」。
公開網頁版不強制連結共用檔案。從 HTTP／HTTPS 網址開啟時可直接使用瀏覽器本機資料；只有需要讀寫院內 FTP JSON 時，才由右上角自行連結。
每次開啟

連結 FTP 共用 JSON

  1. 在阻擋視窗按橘色的「開啟 FTP 共用檔案」。
  2. Windows 檔案選擇器出現後，進入院內 FTP 的共用子資料夾，選取唯一的 DocCCC-data.json。
  3. 若 Edge／Chrome 詢問是否允許變更檔案，請按「允許」。完成後網頁會直接載入資料並開始作業，不需再按網站內的第二個按鈕。
  4. 右上角出現綠點與「FTP JSON 已連結／已同步」後才開始輸入。
連結成功

先認右上角的儲存狀態

1綠色狀態代表目前已連結 FTP JSON。2「儲存 JSON」可在網路恢復後或關閉前手動再同步一次。

  • 顯示「已同步」：可以安全關閉。
  • 顯示「同步中／待同步」：先等候，不要立刻關閉。
  • 顯示錯誤：先保留頁面，確認 FTP 可讀寫後按「儲存 JSON」。
開始新一期前

設定期別與住院醫師名單

  1. 第一次使用或人員異動時，進入「名單設定」。
  2. 在姓名欄輸入住院醫師；需要增加同年級人員時，按對應的「新增 R1／R2／R3／R4」。
  3. 回到六大核心後，以「新增期別」建立新一期。新期別會複製當下名單，但歷史期別名單不受影響。
  4. 期別名稱可用「更改期別名稱」修正，不需要密碼。
已有評核、暫存或相關資料的人員不能直接從名單移除。請保留歷史紀錄，下一期再調整名單。
主要流程一

六大核心：新增一張評核表

  1. 進入「六大核心」。
  2. 確認目前期別。
  3. 按橘色「＋ 新增表單」。
  4. 選擇住院醫師、評核日期並輸入住院醫師指定的評分教師，再建立表單。同一位住院醫師同一期可依日期建立多張。
六大核心

先學生自評，再由具名教師評分

  1. 學生按「填寫學生自評」，六項能力各選 L1–L5，確認後提交。提交後即鎖定。
  2. 學生完成後，「填寫教師評分」才會開放。畫面會同時顯示「目前評分教師」與住院醫師原指定教師。
  3. 姓名正確時點「確定我是評分教師」；需要換人時才點「變更評分教師」並輸入新姓名。完成確認前，評分欄位不會開放。
  4. 20 個分項各選 N/A 或 1–5 分，再完成六項整體 Level；N/A 不列入得分與滿分分母。
  5. 尚未填完可按「暫存」；再次開啟時，暫存姓名會成為目前評分教師，只要再次確認即可續填，不必重選變更。
  6. 全部確認後按「確認並提交」。教師提交後會鎖定；雙方完成後顯示教師綠色絕對分數圖，以及學生紅色／教師藍色 Level 六角圖。
六大核心

提交與暫存的差別

動作用途之後能否直接修改
暫存教師尚未填完，先保存目前內容。可以，之後繼續填寫。
確認並提交內容已完成，成為正式評核。不可以；需使用管理密碼解鎖。
六大核心

N/A：只扣除有效滿分，不當成 0 分

N/A 計分範例：PC 原本 8 項、滿分 40；若 1 項 N/A，其餘 7 項皆得 5 分，結果顯示「PC 病人照護（滿分40）　35/35（100%）｜N/A 1項」。
獨立參考頁

美國 RT‑Milestones：邊看邊評分

  1. 在六大核心與 Core EPAs 之間按「美國RT- Milestones ↗」。
  2. 瀏覽器會另開 milestones.html；原評分頁不會被切走。
  3. 把兩個視窗拖到螢幕左右兩側，即可一邊展開中文參考，一邊輸入成績。
  4. 此頁唯讀，不讀寫 JSON，也不保存任何評分。
若按入口後找不到頁面，確認 milestones.html 與 index.html 位於同一個本機資料夾。
主要流程二

Core EPA：同一人可建立多張日期表單

  1. 進入「Core EPAs」，選擇期別與受評住院醫師。
  2. 按橘色「＋ 新增表單」，選評量日期並輸入住院醫師指定的評分教師。每次評量建立一張，不需選學員類別。
  3. 上方「評量表」選單可切換同一人的各張日期表單。
  4. 藍色「匯出 PDF」會輸出目前選到的這一張。
Core EPA

具名教師填寫、暫存或正式提交

  1. 先查看目前評分教師與原指定教師；姓名正確時點「確定我是評分教師」，需要換人才選「變更評分教師」。
  2. EPA1–EPA11 每項選 1–5；確實無法評量時可選「未評量」。
  3. 依需要填寫對學員、導師與訓練計畫／科部的建議。
  4. 未完成按「暫存目前表單」；下次開啟只需再次確認暫存的目前教師即可續填。確認完成後按「確定並提交」。
  5. 提交後整張鎖定，重開瀏覽器仍保持鎖定。
統計頁

EPA／六大核心分數統計

進入統計頁後先選期別。每位住院醫師會列出該期多張 Core EPA 供參考，以及六大核心教師正式提交資料的平均。

  • 六大核心只計入教師已正式提交的表單。
  • 每張六大核心先以「有效得分 ÷ 有效滿分」換算 100 分；N/A 不列入分子與分母。
  • Core EPA 僅在統計頁供參考，不會自動帶入 CCC。
  • 不同日期的表單仍各自保存，可由明細追溯。
主要流程三

CCC 評核表：先選日期範圍

  1. 進入「CCC 評核表」，選期別與住院醫師。
  2. 設定六大核心納入起日與迄日。
  3. 系統會找出該日期範圍內、該人教師已正式提交的六大核心表單。
  4. 同一期若有兩三張表單，會先計算每張滿分 100 的分數，再取這些表單的平均帶入 CCC。
  5. Core EPA 不會自動帶入 CCC。
CCC 評核表

完成其餘評核、簽核與提交

  1. 完成 EPA 臨床授權、教學、研究、病歷、病安、CCC 結論、評語與簽核欄。
  2. 尚未完成按「暫存」；確認無誤後按「提交」。正式提交後會鎖定。
  3. 右上「匯出 PDF」輸出目前人員的 CCC 表。網頁表頭的查分 QR Code 與密碼不會出現在 PDF。
需要修正時

管理修改與刪除密碼

六大核心或 Core EPA 正式提交後，如確實需要修正，使用管理密碼：

tsgh123

六大核心

在已完成表單按「修改已提交分數」，輸入密碼並解鎖；修改後儲存。學生與教師資料仍分開處理。

Core EPA

在鎖定表單底部按「輸入管理密碼以修改」，驗證後回到表單修改；按「儲存修改並重新鎖定」後立即再次鎖定。

高風險操作

刪除期別前務必再確認

刪除目前期別也使用管理密碼 tsgh123。

刪除期別無法復原。該期名單、六大核心、Core EPA 與 CCC 資料會一起移除。除非確定整期建錯，否則不要使用。
每天結束前

安全關閉檢查

  • 需要的表單已按「暫存」或「提交」，不是只停留在輸入畫面。
  • 右上角顯示「已同步」。
  • 若剛恢復網路或不確定，按一次「儲存 JSON」，等到「已同步」。
  • 再關閉分頁或瀏覽器。
瀏覽器本機也會保留一份資料，但多人共同作業時，FTP 的 DocCCC-data.json 才是大家交換最新版的共同檔案。
進階功能 · 一般每天不需使用

備份匯出與匯入

功能什麼時候用注意事項
儲存 JSON同步狀態不確定、FTP 剛恢復，或關閉前想再確認。會寫回本次開啟時選定的同一個 DocCCC-data.json。
匯出資料製作額外完整備份、版本更新前留存。下載的是另一份備份檔，不是日常多人共用流程。
匯入資料從完整備份還原整套資料。會取代目前資料，確認備份內容與日期後才操作。
進階功能

多人同時修改時，系統怎麼合併

  • 不同人、不同表單或不同欄位：自動取聯集，兩邊都保留。
  • 空白與非空白：通常保留非空白；若某人明確清空且修改時間明顯較新，會保留新的清空結果。
  • 同一欄位修改時間相差超過五分鐘：採較新的版本。
  • 同一欄位在五分鐘內兩邊都修改：無法安全判斷，會請使用者選擇本機、FTP，或合併兩邊文字。
  • 已正式提交／鎖定的資料發生衝突：不會靜默覆蓋，需管理密碼確認。
最有效的預防方式：同一時間避免兩位使用者編輯同一位住院醫師的同一張表單。
排除問題

常見狀況快速處理

狀況處理方式
一直要求重新選共用資料確認是從本機硬碟開啟 index.html，不是從 FTP／UNC 網路位置執行；再重新選取 FTP 上唯一的 DocCCC-data.json。
選了 JSON 但沒有進入系統查看瀏覽器是否正在等待原生權限確認；若有就按允許。網頁不會再顯示第二個授權按鈕。若仍失敗，改用最新版 Microsoft Edge 或 Google Chrome。
Milestones 入口打不開把 milestones.html 與 index.html 放在同一個本機資料夾。
右上角不是「已同步」不要先關閉。確認 FTP 仍可存取，按「儲存 JSON」；若仍失敗，先匯出完整備份留存，再請管理者檢查 FTP。
JSON 變成 0 KB 或損壞停止其他電腦繼續寫入，先以最近的完整備份還原。正常連結既有 JSON 應使用「開啟 FTP 共用檔案」，不要用另存新檔流程覆蓋既有檔案。
出現衝突選擇視窗比較畫面上的時間與內容；知道哪一版正確就選該版，兩邊文字都要保留時選「合併兩邊文字」。

本手冊只涵蓋一般評分、管理修改與資料交換流程；未說明稽核紀錄頁。若仍無法排除，請保留錯誤畫面、發生時間與當時操作步驟，再交由系統維護者確認。
